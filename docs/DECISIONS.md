## 핵심 결정

## 2026-10-01 — Refresh token: 해시 저장 + 일회용 회전 + 재사용 시 전체 무효화

- **무엇을 정했나**: refresh token은 32바이트 난수. DB에는 SHA-256 해시만 저장. 쓸 때마다 폐기하고 새로 발급(회전). 폐기된 토큰이 다시 오면 그 사용자의 토큰을 전부 폐기하고 재로그인시킨다.
- **후보**: (저장) 서버 저장 안 함(JWT) / 원문 저장 / 해시 저장. (수명) 만료까지 재사용 / 일회용 회전. (저장소) DB 테이블 / Redis.
- **왜 이걸 골랐나**: 서버에 저장해야 로그아웃·탈취 대응이 가능. 해시 저장은 DB 유출 대비. 기기에서 탈취된 경우는 해시로 못 막으므로 회전 + 재사용 감지로 막는다. 저장소는 사용자별 기록이 남는 DB.
- **버린 것의 대가**: 요청마다 DB 조회가 생겨 완전 무상태가 아니다. 응답 유실 후 재시도, 탭 두 개의 동시 갱신 같은 정상 상황도 재사용으로 판정되어 강제 로그아웃된다(유예 시간 없음). 로그아웃한 토큰을 다시 보내도 같은 판정이 난다.

## 2026-09-04 — 로그인 실패 응답은 원인을 구분하지 않는다

- **무엇을 정했나**: 이메일이 없든 비밀번호가 틀리든 동일하게 401 + "이메일 또는 비밀번호가 올바르지 않습니다." 이메일이 없어도 가짜 해시로 BCrypt를 한 번 돌려 응답 시간까지 맞춘다.
- **후보**: (a) "가입되지 않은 이메일" / "비밀번호 틀림" 구분 (b) 동일 메시지
- **왜 이걸 골랐나**: 구분하면 공격자가 가입된 이메일 목록을 무료로 얻는다(계정 열거). 시간 차도 같은 정보를 흘리므로 함께 막는다.
- **버린 것의 대가**: 정상 사용자가 "가입을 안 했던 건지, 비번을 잊은 건지" 스스로 알 수 없어 UX가 조금 나빠진다. 실무에서도 이 대가를 받아들이는 것이 표준.
