## 핵심 결정

## 2026-10-02 — 권한(role)은 토큰의 값을 믿고, 요청마다 DB를 다시 보지 않는다

- **무엇을 정했나**: Gateway는 서명 검증을 통과한 토큰의 `role`로 권한을 판단한다. DB 조회는 하지 않는다. role은 갱신(refresh) 때 DB에서 다시 읽어 새 토큰에 넣는다.
- **후보**: (a) 토큰만 믿음 (b) 요청마다 토큰과 DB를 둘 다 확인
- **왜 이걸 골랐나**: (b)는 가장 안전하지만 요청마다 DB 조회가 생겨 JWT를 쓴 이유(Gateway가 DB 없이 혼자 판단)가 사라진다. access token 수명이 1시간이라 권한 변경은 늦어도 1시간 안에 반영된다.
- **버린 것의 대가**: 관리자 권한을 박탈해도 그 사람의 access token이 만료될 때까지(최대 1시간) 관리자 API가 열려 있다. 즉시 차단이 필요한 서비스라면 블랙리스트(Redis)나 민감 작업에 한한 DB 재확인이 필요하다.

## 2026-10-02 — Refresh 재사용 판정에 유예 시간 10초를 둔다

- **무엇을 정했나**: 폐기된 refresh가 폐기 후 10초 안에 다시 오면 거절만 한다. 10초가 지난 뒤에 오면 탈취로 보고 그 사용자의 토큰을 전부 폐기한다.
- **후보**: (a) 유예 없이 항상 전부 폐기 (b) 유예 10초 (c) 재사용 감지 제거
- **왜 이걸 골랐나**: 동시성 실험에서 (a)는 요청 2건만 겹쳐도 매번 강제 로그아웃되는 것을 확인했다(TROUBLES 참고). 훔친 토큰은 보통 바로 쓰이고 정상 사용자는 한참 뒤(다음 갱신 때)에 오므로, 일반적인 탈취는 유예와 무관하게 감지된다.
- **버린 것의 대가**: 공격자와 정상 사용자의 사용이 10초 안에 겹치면 감지하지 못한다. 그리고 재사용 감지 자체의 한계는 그대로다. 정상 사용자가 돌아와야 감지되고, 돌아오지 않으면 공격자가 계속 갱신할 수 있다(최대 세션 기간, 새 기기 알림 등으로 보완해야 함).

## 2026-10-01 — Refresh token: 해시 저장 + 일회용 회전 + 재사용 시 전체 무효화

- **무엇을 정했나**: refresh token은 32바이트 난수. DB에는 SHA-256 해시만 저장. 쓸 때마다 폐기하고 새로 발급(회전). 폐기된 토큰이 다시 오면 그 사용자의 토큰을 전부 폐기하고 재로그인시킨다.
- **후보**: (저장) 서버 저장 안 함(JWT) / 원문 저장 / 해시 저장. (수명) 만료까지 재사용 / 일회용 회전. (저장소) DB 테이블 / Redis.
- **왜 이걸 골랐나**: 서버에 저장해야 로그아웃·탈취 대응이 가능. 해시 저장은 DB 유출 대비. 기기에서 탈취된 경우는 해시로 못 막으므로 회전 + 재사용 감지로 막는다. 저장소는 사용자별 기록이 남는 DB.
- **버린 것의 대가**: 요청마다 DB 조회가 생겨 완전 무상태가 아니다. 응답 유실 후 재시도, 탭 두 개의 동시 갱신 같은 정상 상황도 재사용으로 판정되어 강제 로그아웃된다(유예 시간 없음). 로그아웃한 토큰을 다시 보내도 같은 판정이 난다.

## 2026-09-04 — 로그인 실패 응답은 원인을 구분하지 않는다

- **무엇을 정했나**: 이메일이 없든 비밀번호가 틀리든 동일하게 401 + "이메일 또는 비밀번호가 올바르지 않습니다." 이메일이 없어도 가짜 해시로 BCrypt를 한 번 돌려 응답 시간까지 맞춘다.
- **후보**: (a) "가입되지 않은 이메일" / "비밀번호 틀림" 구분 (b) 동일 메시지
- **왜 이걸 골랐나**: 구분하면 공격자가 가입된 이메일 목록을 무료로 얻는다(계정 열거). 시간 차도 같은 정보를 흘리므로 함께 막는다.
- **버린 것의 대가**: 정상 사용자가 "가입을 안 했던 건지, 비번을 잊은 건지" 스스로 알 수 없어 UX가 조금 나빠진다. 실무에서도 이 대가를 받아들이는 것이 표준.

## 간단 기록 (기본 결정, 한 줄씩)

- 2026-10-02 — 권한 규칙은 Gateway Filter 한 곳에. 공개 경로는 정확히 일치(좁게), 보호 경로는 `/admin/` 앞부분 일치(넓게). 뒤쪽 서비스도 role 헤더를 한 번 더 확인.
- 2026-10-02 — 첫 관리자는 가입 API가 아니라 앱 시작 시 `.env`의 계정으로 생성. 기본 비밀번호는 두지 않음.
- 2026-09-04 — DB를 MySQL → PostgreSQL로 전환. JPA라 코드 차이 없음, 최근 추세를 직접 써보기 위해. 전환 비용은 초기라 거의 0.
- 2026-09-03 — 로컬 DB는 Docker(compose)로. 비밀값은 `.env`(git 제외) + `.env.example`(커밋)로 분리.
